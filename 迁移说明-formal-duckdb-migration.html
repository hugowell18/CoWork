1整体迁移情况

把 daily_basic 数据集的 2026-05 一个月窗口，从源 DuckDB 正式迁移到可移植 Parquet，并已切换生产查询入口（切换后观察 decision = keep，稳定）。切换对上层查询透明：SELECT ... FROM daily_basic 会自动把 2026-05 路由到 Parquet、其余月份落回 DuckDB，结果与直查源库逐行完全一致。

3每层数据的用法（自底向上）

层文件用途谁读它
① 数据层part-000.parquet真正的列式数据（75018 行）。平台无关。DuckDB read_parquet()
② 清单层manifest.json指向 parquet + 行数/日期/checksum/血缘/质量状态(quality-passed)。用于校验与追溯。路由器解析目标文件
③ 路由层query-entry/daily_basic.json生产开关：声明"2026-05 走 Parquet 清单、其余走源 DuckDB 回退"。存在=切换生效，删除=回退全 DuckDB。query-entry-router.mjs
④ 契约层dataset-contracts/daily_basic.json逻辑键(ts_code,trade_date)、月分区、列/精度/空值规则。校验 / 规范化
⑤ 消费层query-entry-router.mjs + duckdb-client.mjs路由器读指针→构造 UNION 查询(parquet 分支 + 源 DuckDB 分支)；集成进 client，无指针时与旧行为逐字节等价。你的策略/查询代码
核心机制：③ 路由指针让 daily_basic 的查询自动"5月→Parquet、其余→DuckDB"，对上层完全透明。已用同一 DuckDB 引擎独立验证：路由视图与直查源库 双向 EXCEPT = 0（逐行一致），5月=75018、6月=39872 均与源匹配。

4拷贝到 MacBook 无缝切换

第 1 步 · 拷这 5 个文件（务必保持相对目录结构）

假设 Mac 上工程根为 ~/Cowork 与 ~/Quanttrading/Quanttrading：

~/Cowork/data/staging/formal-duckdb-migration/daily_basic/month=2026-05/<run>/part-000.parquet
~/Cowork/data/clean/daily_basic/_versions/month=2026-05/<version>/manifest.json
~/Cowork/metadata/query-entry/daily_basic.json
~/Cowork/metadata/dataset-contracts/daily_basic.json
~/Quanttrading/Quanttrading/server/db/query-entry-router.mjs
~/Quanttrading/Quanttrading/server/db/duckdb-client.mjs   # 若整个 Quanttrading 一起同步则已含
为什么结构必须一致：路由指针和清单里用的都是项目相对路径（已确认没内嵌 C:/ 绝对路径），Mac 上靠运行时传入的 workspaceRoot 拼接解析。清单里那个 absolute_path: C:/Workspace/Cowork/... 只是记录信息，路由器不使用它——所以在 Mac 上不会因为盘符不同而失效。

第 2 步 · Mac 上启用路由（二选一）

A. 走集成好的 client（与生产一致，推荐）：

const client = await openDuckDb('~/Quanttrading/Quanttrading/data/quant.duckdb', {
  queryEntry: {
    enabled: true,
    pointerPath: '~/Cowork/metadata/query-entry/daily_basic.json',
    workspaceRoot: '~/Cowork',        // ← Mac 上的 Cowork 根
  },
});
const { rows } = await client.queryEntry.dailyBasic.all();  // 5月自动→parquet, 其余→duckdb

或用环境变量：QUERY_ENTRY_ROUTING=1 + QUERY_ENTRY_DAILY_BASIC_POINTER=... + QUERY_ENTRY_WORKSPACE_ROOT=~/Cowork

B. 只看/验证数据，不接生产：

-- Mac 上 DuckDB 直接查那份 parquet (75018 行)
SELECT * FROM read_parquet('~/Cowork/data/staging/.../part-000.parquet')
WHERE trade_date BETWEEN '2026-05-01' AND '2026-05-31';

第 3 步 · 回滚（如需）

删除 ~/Cowork/metadata/query-entry/daily_basic.json → 立即回退成"全走 DuckDB"（无指针=旧行为）。源库完好，零风险。

5要注意的现实

  • 目前只有 2026-05 一个月在 Parquet。Mac 上查 daily_basic 其它月份仍会走 quant.duckdb——所以那 2.6GB 源库在 Mac 上你也得有（除非只用 5 月）。要"整个 daily_basic 脱离 DuckDB"，需把所有月份都过一遍 M4→M5→切换。
  • parquet 在 data/staging/（不是 data/clean/_versions/，那里只有清单指过去）。拷贝别漏。
  • 扩展（更多月份 / moneyflow / bar_minute / 全量）= 新一轮 approved requirement→design→tasks 链，重复这条流水线；bar_minute 还需先批准契约更新。
  • 切换/观察脚本有过 2 处 recording-path 小 bug（已靠恢复运行更正，不影响指针与数据完整性），建议后续统一清理。
