# 产品规则

## 定位

Cowork 是一个本地协作控制层，用来让多个独立 Agent 在同一个工程目录中按规格协作。

它的核心价值不是替 Agent 写业务需求，而是保证所有工作都经过清晰的门禁和评审循环：

```text
需求确认 -> Codex 产出 -> Claude 评审 -> Codex 返工 -> Claude 接受 -> 人工负责人最终裁决
```

## 共通目标

- 所有新工作先形成可审阅的需求文档。
- 需求确认前，不进入设计。
- 设计经过 Claude 接受和人工负责人最终批准前，不拆执行任务。
- 任务拆解经过 Claude 接受和人工负责人最终批准前，不启动 Agent 执行循环。
- 所有执行、评审、验收都落到本地状态和 artifact，而不是只存在聊天上下文里。

## 角色

- 人工负责人：确认方向、范围、验收标准和争议裁决，始终是最终裁决者。
- 具体执行按能力划分（architect / implementer / reviewer / tester，定义见 `.kiro/roles/`），由每个 spec 自己的 `bindings.json` 声明这次由谁扮演哪个能力，而不是把 Codex/Claude 的身份写死在 steering 里。
- 祖父条款：没有 `bindings.json` 的 spec 继续按其现有 loop 文件里的身份表述运行——例如 Codex 是主要执行者、Claude 是评审与测试反馈者——不受本条更新影响。

## 非目标

- 不让 Agent 直接互相聊天来替代状态文件。
- 不在需求阶段生成执行任务。
- 不用口头约定替代资源声明、状态记录和验收记录。
- 不默认执行高风险动作，例如推送代码、删除文件、改写历史数据或变更生产式资源。
